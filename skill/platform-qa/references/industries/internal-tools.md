# Internal tools

Covers back-office apps, admin consoles, operations dashboards, request and approval tools used by a company's own staff.

| Role | Feature | Why it matters |
|---|---|---|
| Staff | Sign-in through the company's identity provider | No separate passwords to manage |
| Staff | See only what their team or role needs | Least privilege |
| Staff | Submit requests with status tracking | Replaces chasing people by message |
| Staff | Bulk actions with preview and confirmation | Saves time without mass mistakes |
| Staff | Undo or reverse recent actions | Mistakes in back-office tools are costly |
| Staff | Saved filters and views | Repeated daily work |
| Approver | Approval queue with reasons and delegation when away | Work does not stall |
| Admin | Role and team management synced with the directory | Leavers lose access automatically |
| Admin | Configuration without code changes (lists, thresholds) | Fewer engineering requests |
| Admin | Complete audit log with export | Security and compliance reviews |
| Admin | Data import with validation and a dry run | Bad imports are hard to undo |
| Admin | Reports and scheduled exports | Management reporting |
| Admin | Health view of background jobs and integrations | Failed syncs found early |
| System | Confirmation for destructive actions | Prevents accidental deletes |
| System | Sensible limits on exports of personal data | Data leaks through exports |
| System | Clear ownership: who maintains the tool | Unowned internal tools rot |

This catalogue is a starting point. Check the app's own docs and decisions before calling anything missing.
